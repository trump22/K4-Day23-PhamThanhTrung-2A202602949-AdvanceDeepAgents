# Comprehensive Survey of Large Language Model Agents and Tool Use

## TL;DR (3-5 concise findings, each cited)
- **Synergy of Reasoning and Action:** Foundational paradigms such as ReAct interleave verbal reasoning thoughts with external API actions, overcoming chain-of-thought hallucination and error propagation in interactive tasks [1].
- **Autonomous Tool Acquisition and API Integration:** Models can teach themselves to invoke external APIs through self-supervised fine-tuning (Toolformer) and adapt dynamically to evolving API specifications and document repositories (Gorilla) [2][3].
- **Workflow Optimization and Dynamic Coordination:** Recent methodologies advance beyond static pipelines by formulating multi-agent workflows as activity-on-vertex graphs (Flow) and optimizing recurring tool sequences into deterministic meta-tools to reduce latency and cost [4][5].
- **Safety, Verification, and Reliability Challenges:** Comprehensive evaluations reveal severe security vulnerabilities—such as 66.5% of malicious issues bypassing guardrails in coding agents and widespread vulnerability to indirect prompt injections—driving the adoption of pre-execution temporal verification layers and rigorous safety-compliance benchmarks [6][7][8][9].

## Background (definitions and foundational work)
Large Language Models (LLMs) have traditionally been constrained by static parameter memory, limiting their capability in tasks requiring up-to-date information, precise numerical computation, or physical-world execution. To overcome these limitations, recent literature defines **LLM agents and tool-use systems** as compound AI architectures where a frozen or fine-tuned foundational LLM acts as the cognitive core ("brain"), equipped with memory modules, planning mechanisms, and an expanded action space encompassing external tools, code interpreters, and RESTful APIs [10]. 

Foundational developments established core interaction paradigms. Yao et al. (2023) introduced **ReAct**, a prompting framework that synergizes reasoning and acting by allowing models to generate interleaved verbal reasoning traces ($\mathcal{L}$) alongside environment actions ($\mathcal{A}$) [1]. This design empowers models to create, maintain, and dynamically adjust action plans while incorporating environmental feedback. Concurrently, Schick et al. (2023) proposed **Toolformer**, demonstrating that language models can be trained in a self-supervised manner to decide which APIs to call, when to invoke them, and how to integrate numerical or factual outputs into token generation [2]. Addressing the challenge of massive and frequently updated tool repositories, Patil et al. (2023) developed **Gorilla**, a fine-tuned model leveraging retrieval-aware training to generate accurate API calls and adapt to test-time documentation shifts without catastrophic hallucination [3]. Comprehensive literature reviews synthesize these milestones into unified architectural taxonomies, mapping the evolution from isolated zero-shot function calling to fully autonomous single-agent and multi-agent workflows [10].

## Architectural Paradigms in Tool Integration
The integration of external tools into LLM architectures has progressed from rudimentary retrieval-augmented generation (RAG) to sophisticated, multi-modal execution environments. Early tool-use frameworks relied on explicit function definitions provided in the prompt context, requiring the model to output structured JSON or code snippets that were subsequently parsed and executed by external runtime environments. 

However, static prompt-based function calling proved brittle when dealing with ambiguous user intents, multi-step dependencies, or changing API schemas. To address this, modern frameworks incorporate dynamic retrieval-augmented agentic loops (Agentic RAG) where autonomous agents iteratively evaluate context requirements, query multiple disparate tool registries, and refine their execution strategies [4]. In specialized domains such as computational chemistry and software engineering, tool-augmented systems employ structured reflection and few-shot trajectory memory to chain generation, verification, and optimization into closed-loop pipelines. These architectures ensure that tool invocations are not treated as isolated one-shot predictions, but rather as persistent interactions within a managed stateful environment.

## Dynamic Workflow Generation and Meta-Tool Optimization
As agentic tasks scale in complexity, single-agent loops frequently suffer from excessive token consumption, high latency, and cumulative error propagation. Recent research addresses these limitations through modular workflow orchestration and execution optimization. 

Niu et al. (2025) introduce **Flow**, a modular framework that defines multi-agent workflows as activity-on-vertex (AOV) graphs [4]. By continuously refining task allocation and workflow structure based on historical performance and parallelism complexity, Flow enables adaptive execution of complex software and data tasks. To mitigate the operational overhead and redundancy of multi-step tool calls, subsequent research proposes **Agent Workflow Optimization (AWO)** [5]. AWO analyzes historical execution traces to identify recurring sequences of tool calls and transforms them into deterministic **meta-tools**—composite actions that bundle multiple API invocations into a single execution step [5]. By bypassing intermediate LLM reasoning loops for repetitive subtasks, meta-tools substantially reduce end-to-end latency, operational cost, and failure rates in production agent deployments.

## Formal Verification and Runtime Safety Guardrails
Ensuring the safety and reliability of tool-using agents remains a central challenge, as granting LLMs autonomous access to local file systems, shell environments, and external APIs introduces severe security risks. Unconstrained agents are highly susceptible to indirect prompt injections embedded within tool observations or web content, as well as unauthorized execution of destructive commands.

To establish rigorous runtime guarantees, recent literature incorporates formal verification layers prior to tool execution. For instance, **CaMeLoT** introduces a static verification mechanism that translates an agent's proposed multi-step execution plan into a finite-state transition system labeled with tool provenance and taint information [6]. Using model checkers like nuXmv, CaMeLoT verifies generated plans against temporal logic safety policies before any tool is invoked [6]. By rejecting unsafe plans prior to execution, this approach prevents unintended side effects and malicious exploitation without incurring runtime LLM overhead, while providing precise model-checker counterexamples for automated plan repair.

## Evaluation Methodologies, Benchmarks, and Failure Modes
Evaluating LLM tool agents has evolved from measuring isolated single-turn function-calling accuracy to assessing long-horizon trajectory reliability, robustness against environmental unreliability, and adherence to enterprise safety policies. 

Recent benchmarking suites expose critical vulnerabilities in current state-of-the-art systems. **IssueTrojanBench** demonstrates that when AI coding agents are deployed with local file and shell access, 66.5% of malicious issue requests successfully penetrate all agent- and model-level guardrails [7]. Furthermore, **ToolBench-X** reveals that high-performing agents frequently fail under recoverable environmental hazards—such as specification drift, output drift, and execution failures—due to poor hazard diagnosis and recovery strategies rather than inference budget constraints [11]. 

In enterprise web environments, safety and trustworthiness evaluations such as **ST-WebAgentBench** demonstrate that while agents achieve moderate raw completion rates (24.3%), strict Completion-under-Policy (CuP) scores drop to 15.0%, indicating that roughly 38% of successfully completed tasks violate active organizational or safety policies [8]. Complementing these findings, **ToolHazard-Bench** highlights that adversarial environmental injection timing heavily dictates attack success, with earlier trajectory encounters and tail-end response positions yielding maximum vulnerability to indirect prompt injection [9].

## Trends and Open Problems
The literature on LLM agents and tool use highlights several defining trends and critical open challenges:
1. **Transition from Open-Ended Looping to Structured Governance:** The field is actively shifting away from unconstrained, trial-and-error agent loops toward structured workflow graphs, meta-tool optimization, and pre-execution formal verification (e.g., temporal logic checking) [4][5][6].
2. **Robustness Under Environmental Unreliability and Adversarial Conditions:** As evidenced by ToolBench-X and ToolHazard, bridging the gap between clean laboratory benchmarks and messy, untrusted real-world tool environments requires robust error recovery and immunity to indirect prompt injection [11][9].
3. **Policy-Aligned Task Execution:** Balancing task completion with strict hierarchical safety policies remains a major unresolved tension, as current agents frequently execute correct functional actions that violate safety or compliance constraints [8].
